## 💾 硬件需求测算（基于已公布信息）

**显存下限的粗算**：

```
2.8T 参数 × 4 bit (MXFP4) ÷ 8 = 1.4 TB 裸权重
```

1.4 TB 只是权重本体，实际运行还要加：量化缩放元数据、运行时 buffer、激活值、MoE 路由状态、以及 1M 上下文的 KV/状态缓存。**实际集群聚合显存需求会明显高于 1.4 TB**。

**官方建议**：64+ 加速卡的"超节点"（supernode）配置。这个数字反映的是 896 专家做专家并行时对高带宽通信域的需求，不是理论最小值——官方没公布最小可行配置。

**几个常见问题的直接回答**：

| 问题 | 答案 |
| --- | --- |
| 单张 H100/H200/B200 能跑吗 | ❌ 任何单卡都装不下，必须分布式 |
| 单台 8 卡机能跑吗 | 大概率 ❌（8×141GB=1.13TB < 1.4TB 裸权重） |
| 消费级电脑/Mac 能跑吗 | ❌ 完整版死心；等社区极限量化 + CPU offload 的"能亮机"实验也别指望生产可用 |
| Ollama 能跑吗 | ❌ 短期内不现实（1.4TB + 分布式专家并行的架构假设） |
| 国产卡能跑吗 | 🤔 官方内核评测特意带了"另一厂商 GPGPU"，MXFP4 也是开放标准，值得关注适配动态 |

**结论**：K3 自部署是**机构级**游戏（云上预留 64+ 卡或自建超节点）。个人和小团队的正确姿势是官方 API 或等第三方托管平台上架。

## 🏗️ 权重放出后，部署栈长什么样

按官方已披露的信息，一个生产级 K3 部署预计需要：

1. 分布式集群：受支持的加速卡 + 高带宽互联（NVLink/NVSwitch 域或等效）
2. 存储：≥2 TB 高速存储（权重 + 下载临时文件）
3. 推理引擎：含 KDA 支持的 vLLM 版本（等官方合入）
4. 并行配置：张量并行 × 专家并行的拓扑调优
5. OpenAI 兼容 endpoint + 鉴权/限流
6. 监控：显存、卡利用率、延迟、吞吐、专家负载均衡度

**别抢跑**：确切命令等官方部署指南。KDA 是新算子，专家极稀疏是新负载模式，任何"根据经验猜配置"的教程（包括本仓库）都应等实测校验。
