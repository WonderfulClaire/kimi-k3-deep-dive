## 💾 硬件需求测算（基于已公布信息）

**显存下限的粗算**：

```
2.8T 参数 × 4 bit (MXFP4) ÷ 8 = 1.4 TB 裸权重
```

1.4 TB 只是权重本体，实际运行还要加：量化缩放元数据、运行时 buffer、激活值、MoE 路由状态、以及 1M 上下文的 KV/状态缓存。**实际集群聚合显存需求会明显高于 1.4 TB**。

**官方建议**：64+ 加速卡的"超节点"（supernode）配置。这个数字反映的是 896 专家做专家并行时对高带宽通信域的需求，不是理论最小值——官方没公布最小可行配置。

**几个常见问题的直接回答**：

| 问题 | 答案 |
| --- | --- |
| 单张 H100/H200/B200 能跑吗 | ❌ 任何单卡都装不下，必须分布式 |
| 单台 8 卡机能跑吗 | 大概率 ❌（8×141GB=1.13TB < 1.4TB 裸权重） |
| 消费级电脑/Mac 能跑吗 | ❌ 完整版死心；等社区极限量化 + CPU offload 的"能亮机"实验也别指望生产可用 |
| Ollama 能跑吗 | ❌ 短期内不现实（1.4TB + 分布式专家并行的架构假设） |
| 国产卡能跑吗 | ✅ 华为昇腾、阿里云真武 M890 已 Day 0 适配（详见下文） |

**国产卡不是“值得关注”了，是已经跑通了**：华为昇腾 0day 适配（训练侧 MindSpeed MM 在 Atlas 800/900 A3 上完成训练复现；推理侧 vLLM Ascend / SGLang 可部署，昇腾 950 超节点原生支持 MXFP4/MXFP8）；阿里云真武 M890 超节点 Day 0 跑通，官方数据称联合优化后首 token 时延降约 35%、单卡解码吞吐提升 1.8 倍，可稳定支持 1M 上下文。

**不想自建集群但想要“非官方 API”**：Modal、Together AI、Nebius、GMI Cloud、Baseten、Fireworks 等海外托管平台已 Day 0 上架（Fireworks 还支持 Multi-LoRA serving 和训练）；国内千问 AI 平台和阿里云百炼也将提供 K3 API。数据出域约束不硬的团队，这比自建现实得多。

**结论不变**：K3 自部署仍是**机构级**游戏（云上预留 64+ 卡或自建超节点）。个人和小团队的正确姿势：官方 API、第三方托管平台，或者等社区极限量化（权重已就位，量化社区应该很快有动作，本文持续追踪）。

## 🏗️ 部署栈长什么样

按目前已披露的信息，一个生产级 K3 部署需要：

1. 分布式集群：受支持的加速卡 + 高带宽互联（NVLink/NVSwitch 域、昇腾/真武超节点或等效）
2. 存储：≥2 TB 高速存储（权重 + 下载临时文件）
3. 推理引擎：首日支持的 vLLM 或 SGLang（KDA/FlashKDA 已就位）
4. 并行配置：张量并行 × 专家并行的拓扑调优
5. OpenAI 兼容 endpoint + 鉴权/限流
6. 监控：显存、卡利用率、延迟、吞吐、专家负载均衡度

确切参数以 vLLM/SGLang 文档和官方后续部署指南为准。本仓库不猜配置，等首批社区实测（显存占用、吞吐、量化效果）汇总后更新——也欢迎拿 [实测数据投稿](https://github.com/WonderfulClaire/kimi-k3-deep-dive/issues/new/choose) 直接投过来。
