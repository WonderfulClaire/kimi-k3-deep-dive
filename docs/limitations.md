# 五、已知局限与踩坑：官方自曝 + 使用注意

> 官方在发布博客里罕见地列了三条局限，每一条都直接影响生产使用。这里逐条展开，顺带说怎么避。核对至 2026-07-25。

## 局限 1：思维链历史敏感（最容易踩的坑）

官方说法：K3 按“保留思维链历史”模式训练，如果 agent harness 没有按要求回传全部历史思维内容，或把其他模型的进行中会话切到 K3，生成质量会变得非常不稳定。

这条在实际使用里杀伤面很大：很多 agent 框架为省 token 默认裁剪或摘要历史消息，接 K3 直接翻车；“对比测试时同一个会话切换模型”这个常见操作对 K3 无效且有害。

避坑的办法不复杂：优先用官方验证过的 harness（Kimi Code）；自研框架先审计一遍，确认 assistant 消息的 `reasoning_content` 是原样回传的；要切模型就开新会话，别偷懒。

## 局限 2：过度主动（agentic 双刃剑）

官方说法：K3 训练侧重长时程高难任务，遇到小问题或意图模糊时，可能替用户做出预期之外的决定；如果应用要求 agent 在明确边界内行动、不要自由发挥，请在 system prompt 或 AGENTS.md 里加显式行为约束。

这其实是把“24 小时无人值守跑任务”的能力反过来看——它习惯了自己拿主意。在需要精确遵循规格的场景（金融操作、生产变更、合规文档），放任 K3 自由发挥有真实风险。所以：system prompt 里写清“遇到 X 情况必须停下来问”；高危工具（写库、发消息、花钱）一律加人工确认层；项目根目录放 AGENTS.md 声明行为边界，这个约定官方点名支持。

## 局限 3：用户体验仍逊于闭源旗舰（官方承认）

官方说法：尽管整体很有竞争力，K3 与 Claude Fable 5 和 GPT-5.6 Sol 相比在用户体验上仍有可感知的差距。

第三方数据能把这个“差距”具体化：Artificial Analysis 实测 K3 在其评测中产出 1.3 亿输出 token，约为同价位推理模型中位数的 2 倍。话多、思考长，体现在三个地方：简单问题也要走完思考流程，延迟下不来；输出按 $15/M 计费，话多就是烧钱；目前 `reasoning_effort` 只有 `max`，想用低档位换速度都没得选（官方说后续开放）。

## 其他值得知道的事

这几条不是官方列的局限，但上手前最好心里有数：

- “开源”目前的准确状态是“官宣 7/27 当天发布权重”（截至 07-25）。权重、License 条款细节、训练代码/数据的开放范围都以实际发布为准；open weights 不等于 open source，商用前必读 License；
- Arena WebDev 第 1 是仅 1757 票的初步结果；所有榜单排名随新模型发布会变，引用时带上日期；
- 64+ 卡的门槛意味着“能私有化”和“值得私有化”是两回事，算过 TCO 再动手。

## 总结

K3 的局限画像其实非常一致：它是为长时程自主干活极端优化的模型，代价是话多、主意大、对会话历史格式挑剔。顺着这个特性用（大任务、好 harness、明确边界），体验最好；逆着用（短平快、随意裁剪历史、无约束放养），坑最多。
